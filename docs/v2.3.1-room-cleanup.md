# V2.3.1: room cleanup and capacity recovery

## Defect and reproduction

The previous service removed an explicit leaver's slot only in a lobby. During playing/finished matches it retained that identity as though the device had disconnected. Even an empty lobby remained in the room registry until the room TTL, while capacity counted every registry entry.

An isolated local reproduction using the committed `d7480cd` server created five single-host rooms and explicitly left each one. All five empty rooms remained registered and the sixth creation returned `server_busy`. This verifies a code path that can produce the reported production symptom. The private production registry was not inspected, so the exact contents of its five slots at the time of the report are unknown.

## Authoritative lifecycle

- **Explicit leave:** remove the player immediately in every phase, remove socket membership, revoke the stored credential digest, notify remaining members and transfer host ownership. Repeated leave requests safely acknowledge an already-departed socket. The acknowledgement contains `left` and `roomDeleted`; it never claims a remaining room was deleted.
- **Voluntary mid-match departure:** cancel Classic or Evolution immediately, destroy the simulation, discard the old match ID and action-deduplication state, clear readiness, and return remaining players to the lobby. No victory, point, upgrade or self-fall penalty is awarded for leaving. The room retains its configured capacity and must refill before a fresh match.
- **Unexpected disconnect:** reserve the identity for the full configured 60 seconds, regardless of a shorter room TTL. A running action may settle, then gameplay pauses. Valid reconnect restores the same slot/match. The client does not use unload events for cleanup.
- **Grace expiry:** remove expired reservations, cancel an interrupted match and migrate host when needed. Delete the room as soon as its last player/reservation is gone. The server sweeps once per second and also before room-capacity checks, so creation does not have to wait for the next scheduled sweep.
- **Deletion:** one idempotent helper removes the registry entry, destroys physics, clears room state and memberships, and releases the Socket.IO room subscription. There are no per-room timers/listeners to retain; the one server-wide simulation/cleanup timer is stopped on shutdown. Expired-code tombstones are bounded, carry no credentials, and do not count toward room capacity.

The Render configuration remains `MAX_ACTIVE_ROOMS=5`, with no plan, service or infrastructure changes. Connected idle rooms and still-valid reconnect reservations intentionally count toward that limit. Empty rooms do not.

## Client behavior

**离开房间** is visible at the top of an occupied lobby and below the match. The client waits for a positive server acknowledgement before clearing saved room credentials and returning to the menu. A disconnected socket or request timeout leaves identity and room UI intact with an error, allowing retry. Leaving does not claim deletion unless the server actually deleted the final room.

## Verification

```sh
npm test
npm run build
# With the built server running locally and Chrome installed:
SMOKE_PLAYERS=2 npm run test:browser -- --gameplay --lifecycle
SMOKE_PLAYERS=3 npm run test:browser -- --gameplay --lifecycle
SMOKE_PLAYERS=4 npm run test:browser -- --gameplay --lifecycle
node scripts/lifecycle-smoke.mjs
```

Local release verification passed all 73 unit/regression groups, 33 integration groups, 2/3/4-player browser checks, both production builds and the standalone real-grace lifecycle smoke.

The lifecycle integration suite adds 14 groups covering lobby host/guest/final departures, token revocation, host migration, repeated leave, full-grace reconnect, expiry, five-room capacity recovery, sweep-before-create, Classic/Evolution action-time departures at every room size, finished matches, cross-room isolation and resource bookkeeping across repeated cycles. Resource assertions check registry/membership removal, adapter subscriptions, destroyed physics bodies, stable socket listener counts and the shared timer's shutdown; they are not a heap-soak benchmark.

The existing 73 unit/regression groups and 19 earlier integration groups remain included. Browser lifecycle checks emulate a network failure and drop a leave request to verify that timeouts do not erase identity or report success; an acknowledged departure clears storage and its slot can be reused. The standalone lifecycle smoke uses legal client requests, four sequential room creations, and a real 60-second reservation expiry. It does not fill production to five rooms or perform a load test.
