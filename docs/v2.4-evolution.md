# V2.4 Evolution achievements and online screens

Evolution victory requires at least one opponent elimination using each of the five actual pen IDs: wooden, mechanical, ballpoint, highlighter and fountain. `currentPenStage` is the position on the shared route; `completedPenKills` is an independent unique-ID set, serialized as an array in snapshots. Total eliminations (`score`) remain diagnostic and no longer decide victory.

The authoritative engine captures the acting pen type when accepting an action. That type stays fixed throughout the action's falls, before any upgrades. Duplicate victim events and repeated score commits are ignored. Multiple victims from one action complete only that one pen achievement. Self-eliminations never add achievements. Completed achievements survive upgrades, downgrades and respawns. All five IDs must be present before victory; the engine checks this before respawning or advancing the turn. Classic rules and physics are unchanged.

Existing progression behavior remains: each credited opponent elimination advances one stage, capped at four; an actor's self-fall costs one stage after earned upgrades, floored at zero. Multi-kills can skip stages. A player missing an earlier pen achievement can return to that stage through self-fall downgrades; no achievement is granted for a skipped pen. The scoreboard shows completed actual pen names and progress out of five, independently from the current stage.

Every online start/rematch uses a new server-generated cryptographic 32-bit seed. Descending Fisher–Yates shuffles all five pens, including the first pen. All players share this one route for fairness; it stays fixed for the match and is included in authoritative snapshots. Clients cannot submit a route or achievement state. A fresh draw can legitimately equal a previous permutation (1 in 120); rerolling does not guarantee a different order. Explicit local seeds remain reproducible; ordinary local rematches generate a fresh seed.

Online navigation follows the room state: no identity → Home; lobby → Lobby; playing → Match; finished → Results. Home inputs and lobby controls are absent during play. Results display the winner and achievements, with readiness and host-start controls for the same room/capacity. Refresh/reconnect restores authoritative state; disconnect reservations and explicit-leave acknowledgement behavior are unchanged. Active leave or reservation expiry cancels the match without achievement awards.

## Verification

Run `npm test`, `npm run build`, and the Chrome browser suite at 2, 3 and 4 players with `--gameplay --lifecycle`. The achievement suite covers unique pen IDs, repeated kills without victory, multi-victim attribution, self-falls, preserved achievements, full victory, seeded route validity, all 120 Fisher–Yates choice paths and fresh local rematches. Integration tests cover authoritative route/achievement synchronization, rejected client overrides, same-room rematches, reconnect and lifecycle regressions.

Release and production observations are recorded after checks complete. Physical phone/WeChat testing and production saturation/load testing are outside these checks. Public functional tests cannot directly inject deterministic server-side eliminations; deterministic complete-five achievement wins are verified locally.

Local release checks passed: 79 unit/regression groups, 33 real Socket.IO integration groups, production client/server builds, and Chrome gameplay/lifecycle/navigation runs for 2, 3 and 4 players at 375px. Browser checks exercise Home → Lobby → Match → Results, ready/host-start rematches, Evolution route/achievement display, refresh restoration, acknowledged/failed departures and match cancellation back to Lobby. No production rollout is implied by these local checks.
